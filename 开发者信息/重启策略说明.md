# 工业感知节点 (HAAndroid) 重启与自愈策略

## 1. 核心目标
在无人值守的工业现场，视觉感知节点需具备高度的自愈能力，确保在网络波动、系统资源紧张或硬件异常后能自动恢复服务。

## 2. 进程级自愈
- **前台服务 (VisionForegroundService)**：
  - 使用 `startForeground` 提升 OOM 优先级。
  - `onStartCommand` 返回 `START_STICKY`（虽然本项目继承自 `LifecycleService`，默认行为已接近此语义），确保系统在内存压力缓解后重启服务。
  - **WakeLock**：持有 `PARTIAL_WAKE_LOCK` 阻止 CPU 在灭屏后进入深度睡眠，保证感知链路持续运行。

## 3. 硬件/驱动自愈 (G13)
- **相机绑定重试机制**：
  - 在 `VisionForegroundService.startCamera()` 中实现了 3 次退避重试（Backoff Retry）。
  - 若 `bindToLifecycle` 失败（常见于 HAL 驱动忙或 Activity/Service 切换瞬间冲突），服务会等待 800ms 后再次尝试。
  - 若 3 次均失败，服务将停止并记录 `Error` 日志，待下次系统拉起或手动启动。

## 4. 网络与数据传输自愈
- **MQTT 自动重连**：
  - `MqttManager` 内部封装了 Paho 的 `AutomaticReconnect`。
  - 断网期间，`VisionProcessor` 将检测结果存入本地 SQLite (Room) 缓存。
- **离线补报策略**：
  - `VisionForegroundService` 包含 `startSyncTask`。
  - 当 MQTT 恢复连接后，每 5 秒扫描一次数据库，按时间顺序（FIFO）以 `is_historical=true` 标志位补报数据。
  - 采用 QoS 1 确保数据“至少送达一次”，收到确认后才从本地删除。

## 5. 模型初始化自愈 (P0-①)
- **GPU -> CPU 二次回退**：
  - 优先尝试 TFLite GPU 加速。
  - 若遇到驱动不兼容 (`Throwable`)，自动退回 CPU 模式（4线程）重新初始化 `Interpreter`。
  - 确保“有感知的识别”优于“无感知的崩溃”。
